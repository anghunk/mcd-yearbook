**别的年度报告给你一张好看的图。这个报告给你每一个数字的出处。**

把麦当劳历史订单变成一份**可溯源**的年度回顾：18 项指标，160+ 条证据，

## 它和别的年度报告有什么不一样

打开报告，每个指标右下角都有一个按钮：

```
┌────────────────────────────────────────────────┐
│ 最常点的单品                                    │
│ 可乐中杯 × 8                        [查出处 · 8] │
│ 口径：把所有订单（含套餐）展开成最小商品单元后   │
│       按份数计数。                              │
├────────────────────────────────────────────────┤
│ MCP Tool   │ 定位符            │ 字段            │
│ order-list │ DEMO-2026-0002    │ comboItemList…  │
│ order-list │ DEMO-2026-0003    │ comboItemList…  │
└────────────────────────────────────────────────┘
```

点一下「查出处」，下面直接展开**这条结论来自哪些订单、哪个字段、取什么值**。

| | 常见年度报告 | 麦麦年鉴 |
|---|---|---|
| 输出的数字 | 结论 | 结论 + 出处 |
| 数字来源 | 通常不说明 | 可逐条核查 |
| 数据边界 | 一般不提 | 显式写明覆盖范围与限制 |
| 被排除的数据 | 不提 | 整单退款单列并说明原因 |
| 算错的后果 | 无法发现 | 用户可自查 |

这不是"多做了一个功能"，而是把**可信度本身**做成了产品。

## 真实数据模式

拿到 MCP Token 后（申请地址：https://open.mcd.cn/mcp ，手机号登录 → 控制台 → 激活），
把 Token 填进环境变量，一条命令出报告：

```bash
MCD_MCP_TOKEN=你的token python3 yearbook.py --live --open
```

想反复查看、又不想每次都调接口，就先录制到本地，之后离线运行：

```bash
MCD_MCP_TOKEN=你的token python3 scripts/record_fixtures.py && python3 yearbook.py --from-real --open
```

> `fixtures/real/` 含你的个人订单信息，已在 `.gitignore` 中，**不会被提交**。

## 报告包含什么

**消费概览**
- 数据覆盖范围（含订单数与时间跨度）
- 消费总额、订单数、客单价

**消费结构**
- 最常点的单品、常点单品 TOP5（套餐自动展开为子项）
- 逐月订单数

**习惯画像**
- 最常下单时段、完整时段分布（早餐 / 午餐 / 下午茶 / 晚餐 / 深夜）
- 深夜订单数
- 常去门店、足迹门店数

**营养折算**
- 累计热量、蛋白质、钠（基于官方 `list-nutrition-foods`）

**资产状态**
- 券包：可用 / 已过期
- 积分：可用余额与即将过期积分

**数据可核查性**
- 已剔除的整单退款单独列出

## 设计原则

1. **不猜数字。** 所有数值来自订单、营养表、账户三类输入之一。
2. **不静默降级。** 关键字段缺失直接报错，不填默认值糊过去。
3. **不隐藏边界。** 接口只能取到近期订单，就在报告里写明"不等同于自然年"。
4. **不碰写操作。** 只读四个 Tool，代码层面不存在下单、领券、抽奖的调用。
5. **不引入依赖。** 纯标准库，clone 即可运行，降低任何人验证它的成本。

## 常见问题

**Q：为什么叫"年鉴"但看起来只覆盖几个月？**
A：`order-list` 接口返回的是近期订单，不是完整自然年。报告标题用"年鉴"是产品的
叙事定位，但报告里的"数据覆盖范围"一项会**如实写出实际覆盖的时间跨度**，
不使用"这一年"这类会造成误解的表述。这是刻意的设计取舍。

**Q：报告会上传我的订单数据吗？**
A：不会。所有统计在本机完成，HTML 是纯静态文件，不发起任何网络请求。

**Q：我的账号没有订单，会怎样？**
A：会渲染一份空状态报告，说明可能的原因（尚未下过单，或下单手机号与申请
MCP Token 的账号不一致），而不是显示一串没有意义的零。

**Q：套餐里的商品怎么统计？**
A：套餐会展开成子项计数。点了一份巨无霸套餐，统计的是里面的巨无霸、薯条、
可乐各一份，而不是"巨无霸套餐"这个壳——这样更贴近"我到底吃了什么"的直觉。

**Q：为什么要把整单退款单独列出来？**
A：因为它们被排除在消费统计之外。把"被排除的数据"也展示出来，
用户才能完整核对报告的口径。
